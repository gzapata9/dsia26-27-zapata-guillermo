## Objetivos

1. Consumir APIs de IA con SDKs oficiales.
2. Gestionar secretos con `.env` / variables de entorno.
3. Diseñar un cliente con **mock**, proveedor real y manejo de errores.
4. Citar el uso de IA en el desarrollo cuando proceda.

---

## Bloque A — Exposición (30 min)

### A1. Mapa de proveedores (6 min)

| Proveedor | Uso típico en clase | Auth |
| --- | --- | --- |
| OpenAI | chat / resumen / extracción | `OPENAI_API_KEY` |
| Anthropic | razonamiento / refactor asistido | `ANTHROPIC_API_KEY` |
| Hugging Face | inference API / modelos open | `HF_TOKEN` |
| `mock` | desarrollo sin coste ni red | — |

Coste, rate limits, privacidad de prompts (no subir PII).

### A2. Secretos y configuración (5 min)

- `.env` + `python-dotenv` + `.gitignore`.
- `.env.example` sin valores.
- Nunca hardcodear keys en notebooks que se suben a GitHub.

Demo: `cp .env.example .env`.

### A3. Cliente unificado (12 min) — live

Ejecutar y leer `ai_api_client.py`:

```bash
python ai_api_client.py --provider mock --prompt "Resume SOLID en 3 viñetas"
```

Explicar:

- Dataclass `AIResponse`.
- Errores de dominio `AIClientError`.
- Punto de extensión por proveedor.
- Dónde irían retries/backoff (429, 5xx).

Si hay claves en aula: una demo real corta con un proveedor; si no, mock + código del SDK en pantalla.

### A4. Integración en un pipeline (7 min)

Patrón:

```text
CSV limpio → construir prompt → complete() → guardar JSONL
```

Fallback: si falla el proveedor → mock o cola de reintento.
Puente a E2E (20 oct): este cliente será una etapa del flujo.
